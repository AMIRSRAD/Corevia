# Corevia V1 — executable financial kernel

Version: `0.1.0-SNAPSHOT`
Implemented: 2026-07-12

## Delivered behavior

V1 is the first vertical slice of the greenfield Iranian reference bank. It contains:

- Spring Boot 4.1 and Spring Modulith 2.1 application structure.
- Account creation and balance retrieval.
- Immutable double-entry journals balanced independently for each currency.
- Positive integer amounts; `IRR` input is explicitly rial-denominated.
- Account-currency enforcement and open-account enforcement.
- Deterministic request hashing and idempotent journal/reversal replay.
- Conflict detection if an idempotency key is reused for different work.
- A single linked reversal journal; committed entries are never edited or deleted.
- Ordered row locking and optimistic versions for account balance updates.
- Atomic journal, entry, balance, audit, and outbox writes in one database transaction.
- PostgreSQL Flyway migrations with an isolated local H2 compatibility profile.
- OAuth2 resource-server enforcement in the production profile.
- RFC 9457-style problem responses for validation and financial rule failures.
- OpenAPI 3.1 contract, Java 25 container build, PostgreSQL 18 compose environment, and
  initial Iran/reference-bank configuration packs.

## Financial model

An account stores cumulative debit and credit totals. Its book balance is derived from
its configured normal side:

```text
DEBIT-normal account:  debit total - credit total
CREDIT-normal account: credit total - debit total
```

The journal is authoritative. Balance totals are posting-engine-maintained projections
inside the same transaction. No API can directly change a balance.

Every journal must have at least two entries, every amount must be positive, and total
debits must equal total credits per currency. A journal spanning currencies is accepted
only if each currency is independently balanced; future FX products will add explicit
position and bridge entries.

## Local workflow

Run all verification:

```powershell
.\mvnw.cmd clean test
```

Start the ephemeral development service:

```powershell
.\mvnw.cmd spring-boot:run
```

Create two accounts:

```powershell
$cash = Invoke-RestMethod -Method Post -Uri http://localhost:8080/api/v1/accounts `
  -ContentType 'application/json' `
  -Body '{"accountNumber":"100-CASH","name":"Cash asset","currency":"IRR","normalBalance":"DEBIT"}'

$deposit = Invoke-RestMethod -Method Post -Uri http://localhost:8080/api/v1/accounts `
  -ContentType 'application/json' `
  -Body '{"accountNumber":"200-DEPOSIT","name":"Customer deposit liability","currency":"IRR","normalBalance":"CREDIT"}'
```

Post a balanced one-million-rial journal:

```powershell
$body = @{
  businessDate = '2026-07-12'
  valueDate = '2026-07-12'
  narrative = 'Initial customer funding'
  entries = @(
    @{ accountId = $cash.id; side = 'DEBIT'; amount = '1000000'; currency = 'IRR'; description = 'Cash received' }
    @{ accountId = $deposit.id; side = 'CREDIT'; amount = '1000000'; currency = 'IRR'; description = 'Customer liability' }
  )
} | ConvertTo-Json -Depth 5

$journal = Invoke-RestMethod -Method Post -Uri http://localhost:8080/api/v1/journals `
  -Headers @{ 'Idempotency-Key' = [guid]::NewGuid().ToString(); 'X-Actor-ID' = 'local-operator' } `
  -ContentType 'application/json' -Body $body
```

Repeating the exact request with the same idempotency key returns the original journal.
Changing the request while reusing that key returns HTTP 409.

## Profiles

| Profile | Database | Security | Purpose |
|---|---|---|---|
| `local` | Unique in-memory H2 | Disabled | Fast developer execution only |
| `postgres-local` | PostgreSQL | Disabled | Local persistent integration via Compose |
| `prod` | PostgreSQL | OIDC JWT required | Controlled deployment baseline |

Production requires `COREVIA_DATABASE_URL`, `COREVIA_DATABASE_USERNAME`,
`COREVIA_DATABASE_PASSWORD`, and `COREVIA_OIDC_ISSUER`. Secrets must come from the
deployment secret store, never from a bank pack or repository.

## Module boundaries

```text
accounts  <----- ledger -----> platform
```

- `accounts` owns account state and exposes a narrow posting port.
- `ledger` owns journals, entries, idempotency, validation, and reversal.
- `platform` owns authentication wiring, actor resolution, audit persistence, and outbox.
- The root package owns cross-module HTTP problem translation only.

Spring Modulith/ArchUnit verification fails the build on prohibited dependencies.

## Verification coverage

The test suite proves:

- Application startup and all Flyway migrations.
- Module dependency integrity.
- Successful REST posting and stable idempotent replay.
- Rejection of changed requests under an existing idempotency key.
- Per-currency balance enforcement.
- Account/entry currency agreement.
- Correct debit/credit-derived book balances.
- Reversal produces opposite entries and returns balances to their prior state.
- Journal, entries, balances, audit, and outbox commit or roll back together.

## Explicit V1 limits

V1 is not presented as a production-complete bank. The following remain in subsequent
slices:

- Party/customer/KYC, corporate mandates, maker-checker workflow, and full entitlements.
- Product catalog, Qard al-Hasan and investment-deposit profit allocation.
- Islamic facility contracts, schedules, collateral, delinquency, and provisioning.
- Business-date service, Solar Hijri conversion, holidays, cutoffs, EOD/EOM.
- Available/cleared/blocked balances, holds, limits, overdrafts, and reservations.
- Paya, Satna, Sheba, Sayad/Chakavak, Shetab/Sahab, and Shaparak adapters/certification.
- General-ledger mappings, suspense, settlement, reconciliation, statements, and reporting.
- Outbox publishing, consumer idempotency, workflow engine, notifications, and documents.
- PostgreSQL concurrency/load/HA/backup/DR tests and production infrastructure.
- CBI-controlled specifications, local legal/fiqh validation, penetration testing,
  operational procedures, licensing, and regulator/network approval.

The next implementation slice should add business dates, holds/available balance,
maker-checker approval, and the first Qard al-Hasan deposit product before payment-rail
integration.
